## Looked at and left as they are

- **`packaging/termux-rust.sh` is checked by nothing.** `tools/workflow-shell-check.py` reads only
  the workflows' `run:` blocks and the `bash -c` scripts in them. Adding `packaging/*.sh` to it
  would be a few lines; not done this week, since the other scripts there were not run through
  shellcheck first.
- **An app on its own index dials the helper again every 30 seconds from the thread that asks
  for the status.** A helper that holds the lock but answers no hello within two seconds would
  stall that thread for about two seconds each time. The code reasons about it (a short hello
  wait); it was not seen happening, so nothing was changed.
- **`copy_out` of one file lists a tar whole first** when its list is not in memory yet, so the
  first F5 out of a large compressed tar reads it twice. Once per archive and run, and the list
  is what makes a name given twice safe; accepted.
- **The store's `held` check** runs over every unlisted folder for every row not seen. It grows
  with the folders that could not be listed, which are few.
- **The position index's merge opens its run file for each 64 KiB piece** (`Span::read`), so the
  merge of many runs holds no file open; the open is the price, and a Mac's limit of 256 files is
  why.
- **A watched folder a change names itself is unwatched and watched again.** Between the two a
  change can be missed; the window is microseconds, and the folder is read again anyway.
- **`JAVA_TOOL_OPTIONS` is set to an empty string** for an installed PlantUML run from a folder
  whose name holds `:` and with no options of the user's own. The JVM prints a line about it and
  draws; harmless.
